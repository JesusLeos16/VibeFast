## Concepto: tool use

Tool use es darle al modelo una lista de **funciones que puede invocar**. El modelo decide cuándo llamarlas y con qué argumentos; tú ejecutas la función y le devuelves el resultado. El loop sigue hasta que el modelo da una respuesta final.

VibeFast usa un **registry pattern**: defines la tool una vez, está disponible tanto para tool use (OpenAI) como para MCP (Sem 5).

## Flujo de Kickiie

1. La entrada libre pasa por structured outputs y produce `seguimiento_v1`.
2. Kickiie busca el alumno mencionado dentro de la academia activa.
3. Si hay varias coincidencias, el administrador selecciona la correcta.
4. La UI muestra qué se guardará y pide confirmación explícita.
5. La ruta llama `registrar_seguimiento`, que valida de nuevo el alumno y la
   academia antes de insertar.
6. La invocación queda registrada en `tool_calls` y el evento en
   `eventos_historial`.

## Tool `registrar_seguimiento`

La tool vive en `web/lib/tools/examples/registrarSeguimiento.js` y se registra
en el registry central. No recibe `academy_id` desde el navegador: obtiene la
academia desde la sesión del usuario.

La migración `014_ai_seguimientos.sql` guarda:

- alumno y academia;
- tipo, resumen, prioridad y referencia de regreso;
- nota original y origen `kickiie_ai`;
- usuario que registró el seguimiento;
- estado e idempotency key para evitar duplicar un reintento.

La confirmación está representada también en el contrato de la ruta. Un agente
genérico no recibe automáticamente esta tool mientras no exista un flujo de
confirmación equivalente; la pantalla de Kickiie es el primer consumidor seguro.

## Entregable

Una acción de IA que ejecuta una función real de Kickiie después de confirmar y
deja trazabilidad de la tool utilizada.
